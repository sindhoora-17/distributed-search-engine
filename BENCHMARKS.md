# Benchmarks

## Methodology

- Corpus generated by `scripts/make_dataset.py` (fixed seed → reproducible).
- The benchmark lists the corpus once and partitions files **round-robin into N
  disjoint slices**, one per client thread. Each client indexes only its slice,
  so total work is constant as N varies — this isolates the effect of client
  concurrency on indexing throughput.
- Timing wraps connect → stream all documents → server ack, across all clients,
  measured with `System.nanoTime()`.
- Server and clients on [same machine / describe your setup].

## How to reproduce

```bash
cd app-java && mvn clean package
python3 ../scripts/make_dataset.py ../datasets/bench 2000 1500
# start the server, then:
java -cp target/app-java-1.0-SNAPSHOT.jar \
  com.sindhoora.distributedsearch.FileRetrievalBenchmark localhost 50051 <N> ../datasets/bench
```
